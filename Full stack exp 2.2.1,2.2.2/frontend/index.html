Experiment 2.2.2 — Native Query + Ehcache (JSR-107) Caching

Executes a hand-tuned native SQL query: SELECT * FROM books ORDER BY popularity DESC LIMIT :limit. The response is cached in memory via Ehcache 3 with a 60-second TTL. Subsequent calls are served instantly with zero database load!

CACHE HIT
Response Time: 0 ms Served from Ehcache in-memory cache

Cache hit

O(1) lookup + O(k) response

Ehcache lookup is O(1) on average. Returning and serializing the k requested books takes O(k); no database query runs.

Cache miss

O(N log N) query + O(k) cache write

N is the catalog size and k is the requested result count. The current popularity sort has no index, so its worst case scans and sorts N books before caching k results.
